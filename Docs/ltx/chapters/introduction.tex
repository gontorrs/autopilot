\chapter{Introduction}
\setcounter{section}{0}

Artificial intelligence is changing the way users can interact with digital environments. Traditional human-computer interaction relies on explicit physical input through devices such as keyboards, mice, touch screens, or predefined voice commands. Current voice-based tools already address part of this need. For example, Windows Voice Access allows users to control Windows through spoken commands~\cite{windows_voice_access}, but it is based on a fixed command vocabulary and generally requires the user to guide the computer step by step. This helps in hands-free interaction, but the user still has to perform most of the planning effort.

Other recent systems, such as autonomous cloud-based agents, can interpret free-form natural language and execute multi-step tasks with less guidance. However, they usually depend on remote inference, which implies transmitting screenshots, file names, task descriptions, or intermediate information to external servers. They also tend to operate reactively, observing the screen, choosing the next action, executing it, and repeating the process, instead of generating a complete and reproducible plan before execution.

Recent advances in Speech Recognition, Language Understanding, Visual Perception, and Automated Planning make it possible to move beyond these limitations. Instead of only mapping spoken phrases to predefined commands or relying on remote reactive agents, a system can allow the user to describe an intention and then reason locally about how to execute it. This form of interaction is complex because a computer desktop is not a structured environment by default. The system must transform real screen information, such as windows, icons, text fields, buttons, and changing visual states, into a simplified representation that can be interpreted by artificial intelligence models. It must also convert a human request into a sequence of actions that is not only executable, but also understandable, repeatable, and explainable.

In this context, the problem addressed by this project is the autonomous control of a personal computer through spoken natural language. This problem is relevant not only for accessibility scenarios, but also for situations in which users cannot or do not want to interact with a keyboard and mouse step by step. Examples include temporary physical constraints, multitasking contexts, repetitive desktop workflows, or environments where hands-free interaction is more convenient than direct manipulation.

Autopilot is a fully autonomous desktop automation system for Windows that accepts a single spoken natural language command and executes the described task without any further human interaction. The system operates entirely on the local device without transmitting any data off the device. Its architecture combines a deterministic automated planner with local Vision Language Models (VLMs) and Large Language Models (LLMs), forming a neuro-symbolic pipeline that is evaluated against five alternative systems across performance, reliability, and privacy metrics.

\section{Problem description}

The general challenge is to transform an open spoken request into a correct sequence of desktop actions. A user should be able to describe the desired outcome in natural language instead of issuing one rigid command per interface step. For this to work, the system must understand the intention, extract the necessary task parameters, perceive the current graphical interface, decide which actions are required, execute them, and verify whether the result has been achieved.

This general challenge becomes more specific in the Windows desktop environment. The system must interact with conventional graphical applications through the same interface available to a human user, without relying on privileged application APIs or cloud services. This requirement is especially important when working with private files, local applications, or unstable internet connectivity. It also makes the system useful for accessibility, since users with reduced motor function may benefit from operating the computer through a single spoken instruction rather than a long sequence of manual actions.

Autopilot addresses these limitations by accepting a single free-form voice prompt and executing the described task autonomously from start to finish, with no further interaction required. All inference runs locally on consumer-grade hardware, no data leaves the device at any point, and the action sequence is generated by a deterministic automated planner that produces a minimal and reproducible execution path.

\section{Outline}

The remainder of this report is organised as follows:
\begin{enumerate}
\item \textbf{Chapter~2} presents the state of the art. It reviews the foundations of Automated Planning, including STRIPS, 
Planning Domain Definition Language (PDDL), heuristic search, and Fast Downward, and then introduces sub-symbolic AI through neural networks, Transformers, LLMs, VLMs, and agent orchestration. The chapter concludes by explaining neuro-symbolic AI as the conceptual basis for combining perception, language understanding, and deterministic planning in this project.

\item \textbf{Chapter~3} defines the project goals. It introduces the general goal of building a local voice-based desktop automation system, decomposes it into specific objectives, and describes the validation methods and metrics used to determine whether each objective has been achieved.

\item \textbf{Chapter~4} describes the methodology and work plan. It presents the hardware, models, software stack, planning method, neural perception approach, orchestration strategy, evaluation protocol, development phases, and the main constraints and limitations that shape the project.

\item \textbf{Chapter~5} details the technical development of Autopilot. It explains the system architecture, the role of each pipeline component, the supported task templates, the agent workflow, and the functional and non-functional requirements implemented by the system.

\item \textbf{Chapter~6} reports the experimental evaluation. It covers model selection, internal Autopilot performance, resource usage, timing analysis, comparison against alternative desktop automation systems, evaluation metrics, and the qualitative user study.

\item \textbf{Chapter~7} analyses the ethical implications and social impact of the project. It introduces the relevant legal and ethical frameworks, applies Google's AI Principles~\cite{google_principles} and the Secure AI Framework (SAIF)~\cite{saif} to the system, and evaluates the project across privacy, safety, accountability, bias, accessibility, and scientific validity dimensions.

\item \textbf{Chapter~8} reflects on the author's academic journey at Universidad Francisco de Vitoria (UFV). It connects the project with the author's university experience, technical interests, personal motivation, and future professional direction.

\item \textbf{Chapter~9} presents the conclusions. It summarises the main outcomes of the Final Degree Project (FDP), discusses the degree to which the objectives were achieved, and identifies possible next steps for future work.
\end{enumerate}
